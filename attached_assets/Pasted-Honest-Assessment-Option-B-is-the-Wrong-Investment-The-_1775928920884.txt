Honest Assessment: Option B is the Wrong Investment
The landing page is 598 lines of hardcoded inline styles. Converting it to theme-responsive would mean touching almost every single line — it uses 10+ hardcoded color constants (TXT, MUTED, WHITE, T_L, etc.) passed as style={{}} props throughout. That's a near-complete rewrite of the file.
But more importantly — it shouldn't be fully theme-responsive anyway. Look at what the landing page actually contains:
Section	Background
Nav	Always dark — intentional brand choice
Hero / Features / CTA	#F5FAF7 light green — intentional
"How it works"	#0A2018 dark — intentional design block
Product mockup	Hardcoded — it's a UI preview, not UI
These aren't theme states — they're design decisions. Stripe, Linear, and Vercel all have fixed-aesthetic marketing pages that don't flip with your OS preference. Option B would break that intentional design in exchange for a dark mode nobody expects on a marketing page.

The Actually Correct Long-term Solution
The real inconsistency isn't "the landing page doesn't support dark mode" — it's that the landing page has its own separate navigation system that nobody maintains, duplicates links, has a broken theme toggle, and uses different code patterns from the rest of the app.
The right fix:
1. Remove the landing page's custom <nav> entirely
2. Remove the {!isLanding && <Header />} exclusion in App.tsx — show the shared Header on every page including the landing page
3. Adjust the landing page body to use bg-background / text-foreground for its content wrapper — so the page body does respect dark mode while the green section accents stay as intentional design
Why this works:
* The shared Header (logged out state) already shows exactly what the landing nav shows: "Book a Slot", "Smile Deals", "Clinic Portal" — the tabs are identical
* One nav codebase, zero duplication
* Theme toggle works consistently on every page including landing
* The landing body content responds to theme like every other page
* The dark "How it works" block and green primary accents remain unchanged — they're not theme states, they're design
* The mobile drawer in the landing nav disappears — the shared Header already handles mobile gracefully
Scope: This is moderate work — removing ~90 lines of custom nav code from the landing page, deleting the isLanding condition, and adjusting the outer <div> background from #F5FAF7 to bg-background. The body content can largely stay as-is since most of the sections use primary brand green which is already in the CSS variables.
