🧩 Context for the Agent
System Overview
The clinic dashboard includes tabs: Overview, Clinical, Notes, Actions, Billing.
The goal is to optimize the Billing workflow so that prescriptions, manual entries, payments, and invoices are seamlessly integrated, accurate, and easy for admins to manage.
🧩 Core Modules
1. Pharmacy Stock Catalog (New Side Nav Item)
Purpose: Maintain medicine pricing and stock for auto‑population in billing.
Placement: Add “Pharmacy Stock Catalog” to the side navigation of the clinic dashboard.
Admin UI:
Add Medicine Form: Name, Dosage, Unit Price, Available Qty, Expiry Date.
List View: Table with Edit/Delete/Update Stock actions.
Database Schema:
sql
CREATE TABLE pharmacy_stock (
  id SERIAL PRIMARY KEY,
  medicine_name TEXT NOT NULL,
  dosage TEXT,
  unit_price NUMERIC NOT NULL,
  available_qty INT DEFAULT 0,
  expiry_date DATE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
Integration:
When loading prescriptions, billing fetches medicine prices from this catalog.
If not found → admin can manually enter price and optionally “Add to Catalog.”
2. Clinical Tab (Prescription Entry)
Doctor adds prescriptions with medicine name, dosage, qty, frequency, duration.
Saved in prescriptions table linked to patient + visit.
These prescriptions are later fetched by billing.

🧩 Smart Payment Logic & Edge Cases
Scenario 1: Draft Bill → Paid
Admin marks as paid → invoice generated.
Items locked (cannot edit/remove).
Payment log created.
Scenario 2: Paid Bill → New Prescription Added
System auto‑creates a new draft bill for added items.
Consolidated preview shows both bills grouped.
Admin can mark new bill as paid separately.
Scenario 3: Partial Payment
Bill shows “Collected ₹X, Balance ₹Y.”
When new items added, balance recalculated.
Admin can mark remaining balance as paid.
Scenario 4: Item Removal/Adjustment
Admin removes or edits unpaid items in preview.
Consolidated total updates instantly.
Paid items remain locked.
Scenario 5: Multiple Bills Same Day
Bills grouped under visit/date.
Consolidated statement shows total paid + pending.
Scenario 6: Error Handling
If bill marked paid but new items added later → system auto‑creates new draft bill.
Daily reconciliation ensures every paid bill has valid invoice + no pending items left unbilled.
🧩 Digital Bill Generation

Generate invoice PDF for that bill.
