3. Scroll position issue — root cause analysis
What's happening: The page is a normal document scroll (<div className="container …space-y-6">). When the user selects a clinic, two new sections animate in below the selector — the green clinic profile strip and the date strip. These push all content further down the page. The browser doesn't scroll to compensate, so the date strip (what the user needs next) ends up below the fold and the user must manually scroll to it.
Similarly, inside the booking dialog (Step 1), when a chief-complaint accordion category expands, it pushes the "View Slots" CTA further down inside the overflow-y-auto dialog body — the user has to scroll inside the dialog manually.
Root cause — two separate places:
Trigger	What appears	Issue
User selects a clinic	Clinic profile strip + date strip (slide in below selector)	Date strip goes off-screen — user has to scroll down
User clicks an accordion category (inside dialog)	Sub-issues expand inline	"View Slots" CTA pushed down inside dialog
Proposed fix (no changes yet):
1. Clinic → date strip: add a dateStripRef on the date strip wrapper. A useEffect watching selectedClinic (when it becomes truthy) calls dateStripRef.current?.scrollIntoView({ behavior: 'smooth', block: 'start' }). This brings the date picker to the top of the viewport immediately after the clinic strip animates in.
2. Accordion expand: the shadcn Accordion supports onValueChange. When a category opens, find the accordion item's DOM node via a ref map and call scrollIntoView({ behavior: 'smooth', block: 'nearest' }). This nudges the dialog scroll just enough to show both the trigger and its expanded pills without jarring jumps.
