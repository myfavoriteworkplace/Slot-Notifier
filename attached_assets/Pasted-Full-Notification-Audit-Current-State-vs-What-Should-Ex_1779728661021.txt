Full Notification Audit — Current State vs What Should Exist
What exists today
Infrastructure:
* WebSocket server on /ws/notifications with a clinicSockets map (clinic ID → connected tabs)
* broadcastToClinic(clinicId, data) function
* Notification bell in the clinic admin Header only
* Doctor Dashboard has zero notification infrastructure — no bell, no WebSocket, nothing
Only 1 notification is wired up today:
#	Trigger	Recipient	Channel
✅	Patient books a slot (public flow)	Clinic Admin	In-app bell + toast + WebSocket
Everything else — 12+ actionable events — produces emails/WhatsApp only, with no in-app notification.
