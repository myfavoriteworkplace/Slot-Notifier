What I Found in the Code
1. The "Redundant Preview Panel" — What's Actually Happening
The billing section has two separate rendering blocks:
Block A — "Open Invoice" (lines 1204–1604 in BillingHistoryPanel.tsx) A consolidated card showing ALL open bill items in editable tables (Consultation, Pharmacy, Other), with the Load Prescription + Add Entry toolbar at the top. This is the interactive editing surface.
Block B — "BILLS LIST" (lines 1686–1750) Individual bill cards rendered below, each with their own header (bill number, status badge, amount, Print/PDF button). These repeat the same items already shown in Block A.
So a clinic admin currently sees: Editable table of items → then the same items again in individual bill cards below it. That's the duplication you're seeing. The fix is to collapse both into one — the bill card becomes the editable surface, and the separate "Open Invoice" block above goes away.

2. Dosage Bug — Root Cause Found
The description string when a prescription loads into billing is built like this (line 674):
"Amoxicillin 500mg ×10 OD 5 days"

The parsePharmacyDesc function then splits on ×:
* Medicine = everything before × → "Amoxicillin 500mg" ← dosage is stuck here
* Frequency = "OD"
* Duration = "5 days"
The pharmacy table has no Dosage column at all — Medicine | Frequency | Duration | Qty | ₹/Unit | Total. So dosage "500mg" ends up buried inside the Medicine name cell and is never shown separately. The fix requires: (a) updating the parser to also extract dosage from the medicine name string, and (b) adding a Dosage column to the pharmacy table.

3. Duration "Days" Default
The duration field in the prescription form is a free-text input with placeholder "5 days". The parsePharmacyDesc regex only recognises duration if the stored string contains days/weeks/months/years. If a doctor types "5" or "five", it parses to "" and shows "—" in the billing table.
The fix: split the duration into a number input + unit dropdown (days / weeks) that always saves as "5 days" or "2 weeks" — so it always parses correctly. The dropdown would default to "days" as you requested.

4. Units Column in Doctor Prescription Form
Current MedicineRow structure (stored as JSON in clinical_records.prescription):
{ name, dosage, qty, frequency, duration }

dosage is a free-text field with placeholder "500mg" — the doctor types the number AND unit together.
Your proposed standard table has: Medicine | Dosage | Qty | Freq | Duration | Route | Remarks
What needs to change:
Field	Current	Proposed
dosage	Free text "500mg"	Numeric input + separate units dropdown (mg / mcg / IU / % / mL / tablet / capsule)
route	Doesn't exist	New dropdown: oral / topical / IV / IM / subcutaneous
remarks	Doesn't exist	New text input: "After food", "Avoid alcohol" etc.
duration	Free text "5 days"	Number input + days / weeks dropdown
Because prescription is stored as JSON text in the DB (not a typed column), adding new fields is fully backward-compatible — existing records without the new fields just show "—".
The same fields need to flow through to billing when "Load Prescription" is called — so the description string and the pharmacy table both need updating.
