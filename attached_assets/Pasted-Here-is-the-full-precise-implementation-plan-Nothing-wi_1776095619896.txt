Complete Implementation Plan
1. shared/schema.ts — New table
Add one new table emailOtps:
email — the patient's email address
otpHash — bcrypt-hashed 6-digit code (never stored plain)
expiresAt — 5 minutes from creation
verified — boolean, flips to true after correct OTP entry
verifiedToken — a random 32-char string generated only after successful verification
createdAt — timestamp

Export the insert/select types alongside existing ones. No changes to any existing table or column.

2. server/routes.ts — Two new endpoints + one guard
POST /api/public/otp/send
* Accepts { email }
* Rate-limit: if a valid (non-expired) unverified OTP already exists for this email, return a "already sent, please wait" response rather than spamming
* Generates a 6-digit code, bcrypt-hashes it, writes a row to email_otps, sets expiresAt = now + 5 min
* Sends the OTP email via Resend
* Returns { success: true } (never echoes the code)
POST /api/public/otp/verify
* Accepts { email, code }
* Finds the most recent unverified, non-expired row for that email
* bcrypt-compares the submitted code against the hash
* If correct: sets verified = true, generates verifiedToken (crypto.randomBytes(32).toString('hex')), saves it, returns { verifiedToken }
* If wrong or expired: returns a 400 error
POST /api/public/bookings — add guard
* Now requires verifiedToken in the request body alongside the existing fields
* Looks up the email_otps row: must be verified = true, expiresAt in the future, and the email must match customerEmail
* If valid: proceeds to create booking, sets verificationStatus: 'email_verified' instead of 'pending'
* If invalid/missing: returns 401 "Email verification required"
* Demo clinic path: if the booking is for the demo clinic (identified by the existing demo flag/id in the code), skip the token check entirely
POST /api/public/razorpay/create-order — add same guard
* Same verifiedToken check before creating the Razorpay order — consistent with your confirmation that paid bookings also require OTP

3. server/routes.ts — OTP email template
A new sendOtpEmail(email, code) function using the existing emailShell + detailsTable pattern:
* Header: "Your verification code"
* Large prominent 6-digit code in a detailsTable row
* "Valid for 5 minutes" notice
* No action button (patient just reads the code)

4. client/src/pages/Book.tsx — OTP step in the form
The booking form currently flows: Details → Pick slot → Book/Pay.
The new flow: Details → Pick slot → [Verify Email step] → Book/Pay
Specifically:
* After the patient fills in their email, a "Send Verification Code" button appears next to (or below) the email field
* Clicking it calls /api/public/otp/send and reveals a 6-digit OTP input
* A countdown timer shows remaining validity (5 min)
* A "Verify" button submits the code to /api/public/otp/verify
* On success: a green "Email verified ✓" indicator appears, the verifiedToken is stored in component state, and the "Book" / "Pay & Confirm" button becomes active
* On failure: inline error message, patient can retry or resend
* Demo clinic: the entire OTP step is skipped, Book/Pay button stays active immediately — consistent with the existing demo bypass logic in the file
* A "Resend code" option appears after 60 seconds if the patient didn't receive it
