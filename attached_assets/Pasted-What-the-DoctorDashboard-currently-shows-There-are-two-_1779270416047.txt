What the DoctorDashboard currently shows
There are two separate hero areas:
* Mobile (lines 530–566): A compact green gradient card with the doctor's avatar + name + 3 tiny chips: Total, Today, Upcoming. These are already computed from confirmedBookings.
* Desktop (lines 570–670): A sidebar with an identity card (avatar, name, specialization, degree, clinic), a navigation menu, and a Scan & Share QR card. No stats appear anywhere on desktop.
So the imbalance right now is: mobile has 3 minimal chips, desktop has nothing.

Data already computed and available
Variable	What it contains
myBookings	All bookings assigned to this doctor
awaitingBookings	Bookings where the doctor hasn't approved/declined yet (doctorApprovalStatus === 'pending')
confirmedBookings	Bookings the doctor has accepted
todayBookings	Confirmed bookings for today
upcomingBookings	All confirmed bookings from now onwards
The 4 new stats would need two small additions: "pending in next 7 days" and "confirmed in next 7 days" — both straightforward filters on existing data.

One important distinction vs the clinic dashboard
In the clinic dashboard, "confirmed" means b.status === 'confirmed' (the clinic confirmed the booking). For a doctor, "confirmed" means they've accepted the assignment (doctorApprovalStatus !== 'pending'). These are different fields, so the 4 stats for the doctor would mean:
Stat	Doctor's interpretation
Today Confirmed	Appointments today that I've accepted
Pending Next 7 Days	Assignments awaiting my approval in the next 7 days — most actionable
Total Pending	Full backlog of assignments awaiting my approval
Confirmed This Week	Appointments I've accepted coming up this week
This is genuinely useful — especially "Pending Next 7 Days" since doctors can miss assignment requests buried in the list.
